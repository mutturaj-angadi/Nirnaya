WHAT NIRNAYA DOES

Nirnaya validates a linear model, performs reversible presolve reductions, solves it with its own CPU revised-simplex engine, and checks the recovered solution against original constraints and bounds. GPU device discovery and numerical primitives are provided separately; LP simplex execution is CPU-only in this release.

METHODOLOGY
This artifact runs models through Nirnaya's production orchestrator in-process and compares independently with SciPy/HiGHS. It is not the live HTTP release matrix and not the separate synthetic validation suite. It is not a controlled speed ranking: Nirnaya includes its presolve/recovery path while SciPy/HiGHS applies its own configuration.
Heavy concurrent API requests may contend for CPU and reach their configured time limits; the API currently has no solve admission control.

DEPENDENCY RULE

Core defines the data contracts. Presolve and solver depend on core; API depends on those packages; the browser UI calls only the API. GPU primitives are a leaf capability and do not create a solver/API cycle. SciPy reference code is isolated under validation and benchmark tools.

Security & input boundaries
Implemented controls and their limits.
API ENFORCEMENT
REQUEST BODY5 MiB maximum
MODEL LIMIT200,000 vars / rows
COEFFICIENT ENTRIES5,000,000 maximum
REQUESTED SOLVE TIME600 s ceiling
WALL GUARD900 s cooperative wrapper

The wrapper cannot forcibly terminate a blocked Python worker thread; the solver also checks its own deadline.

MODEL & RESULT HANDLING

Structured JSON schema validation; finite numeric and bounds validation in core; explicit iteration/time limits; deterministic pivot selection; original-space primal verification before OPTIMAL; structured error envelopes without serialized traceback details; no user-controlled shell execution or unsafe object deserialization.

The data audit is read-only and reports anomalies; it does not silently clean or discard model content.

Known boundary: the local SciPy/HiGHS reference tools are validation-only and must not be exposed as the production solve backend.
